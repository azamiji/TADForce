# Méthode {#ax-method}

Les signaux ci-dessous sont **mesurés** sur les métadonnées de l'organisation (et, en mode connecté, sur des agrégats de l'organisation). Un signal est un constat, pas un verdict : chacun est qualifié par l'architecte avant de devenir un axe d'amélioration.

- **Piliers** du cadre Salesforce Well-Architected : *Fiable* (sécurité, conformité, fiabilité), *Simple* (expérience utilisateur, exploitation, conception intentionnelle) et *Évolutif* (maintenabilité, montée en charge, capacité à évoluer).
- **Priorités** : <span class="b p1">P1</span> agir maintenant (risque pour la sécurité, les données ou la continuité) ; <span class="b p2">P2</span> planifier dans les prochaines versions ; <span class="b p3">P3</span> améliorer à l'occasion d'une évolution du domaine.
- Chaque axe porte un identifiant `AX-nn`, repris dans le registre et dans la feuille de route.
