# Method {#ax-method}

The signals below are **measured** on the metadata of the organization (and, when connected, on aggregated org facts). A signal is an observation, not a verdict: each one is qualified by the architect before it becomes an improvement axis.

- **Pillars** follow the Salesforce Well-Architected framework: *Trusted* (security, compliance, reliability), *Easy* (user experience, operations, intentional design) and *Adaptable* (maintainability, scalability, resilience to change).
- **Priorities**: <span class="b p1">P1</span> act now (risk for security, data or continuity); <span class="b p2">P2</span> plan in the next releases; <span class="b p3">P3</span> improve when touching the area.
- Each axis has an identifier `AX-nn`, reused in the register and in the roadmap.

This example was produced offline, from the metadata only: no Code Analyzer report and no org facts (coverage, volumes) were available.
